# Datasheet: Dhammapada RAG corpus (v0.2, Phase 1)

Follows Gebru et al., *Datasheets for Datasets* (2021), scoped to what's
answerable at this stage of the project. Numbers below are computed by the
pipeline in `src/dhammapada_rag/ingest/` against the sources in `data/raw/`
and `sources/external/`; regenerate all four pipeline scripts (in order:
`parse_stories.py`, `validate.py`, `parse_interlinear.py`, `build_verses.py`)
before trusting a stale copy of this file.

## Motivation

**For what purpose was the dataset created?** To support a RAG system over
the Dhammapada that keeps three layers distinct -- verse, aṭṭhakathā
commentary/narrative, and model synthesis -- rather than flattening them, per
`DhammapadaRAG.txt`.

**Who created it, and on whose behalf?** Four independently-published sources
feed this corpus (see "Collection process" below); the structured corpus in
`data/processed/` is derived from them by the pipeline in this repo.

## Composition

Two complementary tables, both keyed by Dhp verse number where relevant.

### `data/processed/verses.jsonl` -- the canonical verse layer, 423/423 complete

One record per Dhammapada verse (1-423). Every verse has: `pali_mahasangiti`
(Mahāsaṅgīti edition, CC0), `english_sujato` (Bhikkhu Sujato's translation,
CC0), `interlinear_pali`/`interlinear_english`/`interlinear_notes`
(Ānandajoti Bhikkhu's 2017 interlinear edition with phrase-level scholarly
notes, CC BY-SA 3.0), and `story_group_ids` (which `stories.jsonl` entries
explain this verse). Where the narrative source itself quotes the verse in
full, that's also kept separately as `narrative_pali`/`narrative_english`/
`narrative_source_group_id` (present for 226/423 verses, 53.4% -- see below;
this is additive context, not a completeness gate, since `pali_mahasangiti`/
`english_sujato` cover all 423 regardless).

`data/processed/verses_report.json`, regenerated by `build_verses.py`:
`pali_mahasangiti`, `english_sujato`, and `interlinear_pali` are each
423/423 (100%). `narrative_pali` is 226/423 (53.4%) -- not a gap in this
table, just a fact about which verses the narrative source happens to quote
in full inline (see `stories.jsonl` composition below for why).

### `data/processed/stories.jsonl` -- the narrative/commentary layer, 305 stories

One instance = one commentarial story (vatthu), keyed by `group_id`
(`{vagga}.{story}`, e.g. `"1.1"`). Each carries the Dhp verse number(s) it
explains, title fields, synopsis/cast/keywords/rating metadata, the narrative
body (split into `nidana`/`vatthu`/`desanavasane` where detected), and
footnotes. Also carries `pali_verse`/`english_verse`/`pali_verse_number`: the
verse text *as this specific story quotes it*, when it does (see below) --
kept distinct from `verses.jsonl`'s critical-edition text because a verse's
recitation context within its own story (Phase 3's parent-assembly design)
is meaningfully different from a standalone quotation of the same verse,
even when the words are nearly identical.

**How many instances?** 305 stories, covering all **423** Dhammapada verses
across all **26** vaggas -- confirmed against both (a) the canonical
26-vagga/423-verse structure hardcoded in `vaggas.py`, independent of any
edition's pagination, and (b) the narrative source's own colophon
(Nigamanakathā, end of text), which states "423 verses... in three hundred
and five stories... 26 Chapters" -- an external check the parser output
matches exactly. `validate.py`'s `passes_hard_validation` is currently
`true`.

**Does the dataset contain all possible instances, or a sample?** All
stories in the narrative source, all 423 canonical verses; no sampling.

**What data does each instance consist of, and is anything missing?**
- `title_en` / `title_pali`: present for effectively all stories.
- `dhp_verses`: present for all 305 (6 required hand-correction, see
  "Preprocessing" below).
- `pali_verse` / `english_verse` (the *narrative* source's own quotation,
  distinct from `verses.jsonl`'s critical-edition text): the source does
  **not** reprint the full numbered Pali verse text at every story -- only
  ~74% of stories (226/305) contain it inline. The other ~26% (79/305,
  flagged `pali_verse_not_in_source`) explain a verse whose companion in the
  same multi-verse group was already fully quoted elsewhere; only a short
  teaser quote appears at these stories, by original editorial design (see
  the translator's introduction). This is why `verses.jsonl` exists as a
  separate, fully-covering table rather than something derived solely from
  `stories.jsonl`. `english_verse` is missing in only 4/305 cases where
  `pali_verse` *was* found (extraction gap, not source gap).
- `nidana` (opening "with reference to whom" pericope): detected in 84.3%
  (257/305); the rest have varied enough phrasing that the regex heuristic
  didn't anchor cleanly -- `vatthu` still contains the full body in those
  cases, just undivided.
- `desanavasane` (closing "fruits of the teaching"): detected in 97.7%
  (298/305).
- **True pada-vibhaṅga (word-by-word commentarial gloss) is absent from
  every source ingested so far.** The narrative source explicitly omits it
  (Burlingame's 1921 translation did, and Ānandajoti Bhikkhu's 2024 revision
  followed suit, intending a separate future translation of it).
  `verses.jsonl`'s `interlinear_pali`/`interlinear_english`/
  `interlinear_notes` fields are the closest available public substitute --
  a line-by-line interlinear Pali/English rendering with inline scholarly
  notes on specific word choices, textual variants, and parallel readings,
  covering all 423 verses -- but this is honestly a *different kind of
  resource* than traditional pada-vibhaṅga (which glosses each word against
  the Abhidhamma/grammatical tradition), not a stand-in that should be cited
  as equivalent. `DhammapadaRAG.txt`'s original nidāna/vatthu/pada-gloss/
  desanāvasāne four-way split is representable now as nidāna/vatthu/
  desanāvasāne (from `stories.jsonl`) plus `interlinear_*` (from
  `verses.jsonl`) rather than a true fourth vatthu-internal segment.

**Is there a label or target associated with each instance?** No; this is a
retrieval corpus, not a labeled training/eval set. The gold evaluation set
called for in Phase 5 is separate, not-yet-built work.

## Collection process

**How was the data acquired?**
1. `sources/Dhammapada-Attakatha.pdf` -> `pdftotext -layout` (poppler
   26.07.0) -> regex/heuristic segmentation
   (`parse_stories.py`) -> `stories.jsonl`. See `data/raw/PROVENANCE.md`.
2. `sources/external/mahasangiti_pali/`, `sources/external/sujato_en/` --
   fetched via `curl` from `suttacentral/bilara-data` (GitHub, `published`
   branch), segmented JSON, joined per verse by `build_verses.py`.
3. `sources/external/anandajoti_interlinear/` -- fetched via `curl` from
   `ancient-buddhist-texts.net` (26 HTML pages), parsed with BeautifulSoup
   (`parse_interlinear.py`) into `interlinear_gloss.jsonl`, then joined in by
   `build_verses.py`.

   All three fetch sources are documented with URLs, license evidence, and
   exact fetch commands in `sources/external/PROVENANCE.md`.

**Over what timeframe?** Narrative source extracted/parsed 2026-07-30;
external sources fetched 2026-07-30 (same day, second pass after the first
Phase 1 review flagged the coverage/licensing gaps below).

## Preprocessing / cleaning / labeling

**stories.jsonl (narrative source):**
- Running per-page headers/footers stripped (regex on the
  `"N. The Chapter about X, Vagga - <page>"` pattern).
- Inline PTS/Burlingame pagination crumbs (`[28.146]`, `{1.3}`) stripped from
  body text.
- Footnotes (numbered, BG=Burlingame's own / AJ=Ānandajoti Bhikkhu's)
  extracted into a separate `footnotes` list per story rather than left
  inline -- an explicit editorial-provenance signal worth keeping
  distinguishable for the "layer attribution" work in later phases.
- **6 stories (2.1, 3.1, 17.7, 18.12, 26.17, 26.34) had their header-stated
  `Dhp N` verse number(s) hand-corrected** after `validate.py` flagged
  missing/duplicated/out-of-range verses. Each correction is logged with its
  textual evidence in `src/dhammapada_rag/ingest/corrections.py` -- e.g.
  story 26.17's header says "Dhp 40" (a typo missing a trailing zero: the
  body quotes verse 400 in full, and Dhp 40 already belongs to a different
  vagga, already covered by story 3.6). **Correction rate: 6/305 = ~2.0%** of
  stories required hand-correction to pass hard validation. All 6 are now
  independently cross-checked against `verses.jsonl`'s Mahāsaṅgīti/Sujato
  text (e.g. story 26.17's corrected Dhp 400 and 26.33/26.34/26.35's Dhp
  416/416/417 split all match the externally-sourced verse text exactly).
- One further known-and-intentional anomaly, **not** treated as an error: Dhp
  416 is explained by two stories (26.33 and 26.34) -- the translator's
  introduction calls this out explicitly as the one place in the whole text
  the source does this. `validate.py` reports this as the corpus's one
  remaining "duplicated verse"; it is expected, not a bug.

**verses.jsonl (merge):**
- Mahāsaṅgīti/Sujato JSON segments (keyed `dhp<verse>:<line>`) joined per
  verse in ascending line order, excluding `:0`/`:0.N` header segments
  (nikāya/vagga/story-title metadata, not verse text).
- Interlinear HTML parsed per verse using the `<span class="number">[N]</span>`
  marker as the verse boundary (not `<div>` boundaries, which span many
  verses each). Inline `<span class="TT">` scholarly notes extracted into a
  separate `interlinear_notes` list and stripped from the Pali/English line
  text. ~180 of the 423 verses are quoted a second time elsewhere on their
  page as an incidental cross-reference from another verse's discussion
  (e.g. "compare v. 322"); the parser keeps the first occurrence in document
  order, which is always the verse's own canonical position, and logs every
  such case.

## Uses

Intended for the retrieval/generation phases of this project (Phases 2-4 of
`DhammapadaRAG.txt`). Not intended as a scholarly critical edition -- for
that, consult the PTS edition, SuttaCentral, or Ānandajoti Bhikkhu's site
directly; this corpus inherits whatever accuracy its sources have, plus this
pipeline's parsing error rate.

## Distribution / license

See `docs/licensing.md`. Summary: two of the four sources (Mahāsaṅgīti Pali,
Sujato's English) are CC0; two (the narrative source's Ānandajoti Bhikkhu
revision layer, and his separate interlinear edition) are CC BY-SA 3.0 by
strong inference from the publisher's site-wide policy, not yet a
document-specific written confirmation -- get that before any public/Zenodo
release.

## Maintenance

Owned by this repo. Re-run, in order, `parse_stories.py` -> `validate.py` ->
`parse_interlinear.py` -> `build_verses.py` after any change to a raw/external
source or to the parsing logic; each stage regenerates its own JSON report so
drift from the numbers in this file is self-detecting
(`data/processed/parse_report.json`, `validation_report.json`,
`verses_report.json`).
